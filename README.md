# AI Support Ticket Triage

AI Support Ticket Triage is a lightweight NLP application that helps support teams sort incoming messages by category and priority. It combines a transparent scikit-learn model with rule-based routing guidance and a Streamlit interface for individual and batch analysis.

## Live Demo

The app is ready for deployment to Streamlit Community Cloud. Until the public URL is added, follow the local setup below.

## What It Does

- Classifies tickets as **billing**, **technical**, **account**, or **general**.
- Predicts **low**, **medium**, or **high** priority.
- Shows separate confidence values and flags uncertain results.
- Highlights influential words and phrases behind the category prediction.
- Suggests a transparent rule-based next action.
- Processes a CSV batch without discarding the original columns.
- Exports analyzed results as CSV.

## Why I Built It

Support queues mix urgent incidents with routine questions. This project explores how a small and explainable NLP pipeline can provide a useful first-pass organization layer while keeping a human reviewer in control.

## Architecture

```text
Message or CSV
      │
      ▼
Input validation
      │
      ├── TF-IDF + logistic regression ──► category + confidence
      ├── TF-IDF + logistic regression ──► priority + confidence
      └── deterministic rules ───────────► suggested next action
```

The Streamlit app is intentionally thin. Reusable modules under `src/ticket_triage/` own validation, modeling, explanations, guidance, and batch serialization so the core behavior can be tested without a browser.

## Model and Dataset

The project trains two independent logistic-regression classifiers on TF-IDF unigram and bigram features. The bundled dataset contains 60 original demonstration tickets balanced across four categories; it contains no real customer data or personal information.

The interface exposes confidence values and influential terms from the category classifier. Suggested actions are deterministic rules—not generated by an LLM.

## Results

The bundled data produces 100% training-set accuracy and macro F1 for both targets. These values are **smoke checks only**, not unbiased estimates of real-world performance: the demonstration dataset is deliberately small and is evaluated on the same examples used for training.

The application therefore labels low-confidence output as uncertain and recommends human review. A real deployment would require a larger independently labeled dataset and a held-out evaluation set.

## Run Locally

Requires Python 3.11 or newer.

```bash
cd ai-support-ticket-triage
python -m venv .venv
```

Activate the environment:

```bash
# Windows PowerShell
.venv\Scripts\Activate.ps1

# macOS or Linux
source .venv/bin/activate
```

Install and run:

```bash
python -m pip install -e ".[dev]"
streamlit run app.py
```

## CSV Format

Batch files must be UTF-8 CSVs with a `message` column. Other columns are preserved in the output.

```csv
ticket_id,message
1001,I was charged twice for the same subscription.
1002,The application crashes whenever I upload a PDF.
```

An upload-ready example is available at [`data/batch_example.csv`](data/batch_example.csv).

## Tests and Code Quality

```bash
pytest -v
ruff check src tests app.py
```

Tests cover message and CSV validation, the dataset contract, training and prediction outputs, evaluation tables, routing guidance, batch-column preservation, CSV export, and the Streamlit entrypoint.

## Limitations

- The dataset is small and written specifically for this demonstration.
- Training-set metrics do not measure generalization.
- The English-only vocabulary will not handle every language or domain.
- Confidence is a model score—not a guarantee of correctness.
- Keyword explanations are local coefficient contributions rather than causal explanations.

## Future Improvements

- Collect and label a larger anonymized support dataset.
- Add a stratified held-out test set and cross-validation.
- Calibrate probability estimates and tune the uncertainty threshold.
- Add multilingual models and domain-specific categories.
- Monitor category drift and reviewer corrections over time.

## Responsible AI Note

This application is a decision-support demonstration. It should not automatically close tickets or make consequential customer decisions. Human reviewers should confirm classifications and routing actions—especially when confidence is low.
